# VTuberの仕草・表情・ダンスを学ぶAI

## 目的

VTuberを、画像を生成するだけのキャラクターではなく、顔・口・手・全身・声・環境を連動させて視聴者とコミュニケーションするインターフェースとして研究する。

中心となる問いは、**キャラクターの一貫性を保ちながら、状況に合った表情や仕草をどう再現・生成・評価できるか**である。

この研究ではLoRAを候補技術のひとつとして扱う。LoRAだけですべてを解決すると仮定せず、画像生成、動画生成、モーション制御、リグ、音声駆動アニメーションを役割ごとに比較する。

## 研究対象

### 1. 顔はインターフェースである

- 眉、目、まばたき、視線、顔の向き
- 口形、発話・歌との同期
- 表情が変化するタイミングと持続時間
- カメラ距離や画角による表情の伝わり方

顔から読み取られる印象と、本人・キャラクターの内面状態は同一とは限らない。研究では観察できる表情と推定した感情を別々に記録する。

### 2. 手とジェスチャー

- 手の位置、手の形、指の動き、左右差
- 指差し、手振り、拍手、顔や胸元に手を寄せる動作
- 発話や音楽のリズムと手の動きの同期
- 手が顔や身体に隠れる場合の扱い

### 3. ダンスと全身動作

- ポーズ、重心、軌跡、速度、反復、動作の切り替え
- 音楽の拍と身体動作の関係
- 同じ振付を異なるキャラクターで再現できるか
- 同じキャラクターの動作スタイルを保てるか

### 4. 口・声・歌

- 音声に応じた口形の変化
- 発話・歌・呼吸のタイミング
- 口だけでなく、頭・手・身体の動きとの連携
- 音声と映像のずれ、発話区間の境界

### 5. 感情表現と環境

- シナリオや会話の状況に応じた表現方針
- 表情・姿勢・動作・声の組み合わせ
- 照明、背景、カメラ、画面構成
- キャラクター表現と環境演出を独立して調整できるか

感情ラベルを内面の事実とみなさず、「喜びを表す演技」「驚いて見える表情」のように、生成・観察可能な表現として扱う。

## 仮説

1. キャラクターの外見と動作スタイルを分けて管理すると、外見の一貫性と動作の多様性を個別に評価しやすい。
2. 顔・口・手・全身を別々に生成するだけでは、タイミングの不整合が起こりやすい。
3. 感情や場面を高水準の演出状態として表現し、具体的な顔・手・身体・環境の動きに展開すると、再現性を測りやすくなる。
4. LoRAの有効性は対象モデルとデータに依存し、時間的な動作の制御には専用のモーション表現や動画モデルが必要な場合がある。

これらは検証前の仮説であり、結論ではない。

## システム案

```text
会話 / 音声 / シナリオ / 環境
              |
              v
      演出状態・タイムライン
              |
      +-------+--------+---------+
      |       |        |         |
     顔・口   手      全身      環境
      |       |        |         |
      +-------+--------+---------+
              |
              v
      キャラクター出力と評価
```

各トラックには開始時刻、終了時刻、対象部位、動作・表情パラメータ、根拠となる入力、生成方式、確信度を記録する。独立制御を維持しつつ、全体の時間軸で同期させる。

## LoRAと他方式の役割分担

| 対象 | 候補方式 | 評価したいこと |
|---|---|---|
| キャラクター外見 | 画像モデルのLoRA、参照画像制御 | 顔・衣装・画風の一貫性 |
| 表情 | 表情条件付け、参照画像、対応モデルの追加学習 | 指定表情の再現性と副作用 |
| ダンス | 動画モデル、モーション条件付け、3Dモーション | 振付、時間的一貫性、リズム |
| 口 | 音声駆動アニメーション、リップシンク | 音声と口形の同期 |
| 手 | キーポイント、モーションデータ、3Dリグ | 指形状、左右、遮蔽への頑健性 |
| 環境 | シーン設定、照明・カメラ制御 | キャラクターと背景の独立制御 |
| 感情演出 | 状態モデル、ルール、タイムライン | 複数チャネルの整合性 |

LoRAは特定のモデルの重みを効率的に適応させる手法であり、データの権利、ベースモデル、学習対象、推論環境を確認してから採用する。

## MVP実験

### 実験A：同一キャラクターの表情

1. 使用許諾のあるキャラクター資料を用意する。
2. ニュートラル、喜びを表す演技、驚きを表す演技の3条件を定義する。
3. 参照画像制御とLoRAなど、少なくとも2方式を比較する。
4. 顔・衣装の一貫性、表情の適合、意図しない変化を記録する。

### 実験B：仕草とダンス

1. 権利上利用可能な短いモーションを選ぶ。
2. 動作を時刻付きのポーズ・軌跡・手の状態として記述する。
3. 元の動作との類似度、時間的一貫性、手や顔の破綻を評価する。
4. 画像LoRAのみの条件と、モーション制御を使う条件を比較する。

### 実験C：口・手・環境の同期

1. 短い音声とシナリオを固定する。
2. 口の同期、手振り、頭部動作、背景・カメラの演出を個別に制御する。
3. 各要素を個別生成した場合と、共有タイムラインで制御した場合を比較する。
4. 同期誤差、キャラクター一貫性、視聴者評価を記録する。

## 評価指標

- キャラクター同一性・衣装の一貫性
- 指定した表情・仕草の再現率
- 動画内の時間的一貫性
- 音声と口形の同期誤差
- 手指・顔の破綻率
- 環境とキャラクターの制御独立性
- 同じ設定での再現性
- 推論時間、学習コスト、データ準備工数

可能であれば自動指標と人間評価を併用し、評価データが学習データと重複しないようにする。

## データと倫理

- キャラクター、声、ダンス映像、モーションの利用許諾とライセンスを確認する。
- 実在人物の顔・声・動作を扱う場合、同意と用途を明確にする。
- 配信者の感情や心理状態を、表情だけから断定しない。
- 学習データの偏り、衣装や体型、文化的表現の偏りを確認する。
- 元データ、前処理、モデル、LoRA設定、プロンプト、評価結果を記録する。
